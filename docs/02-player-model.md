# 02. 선수 데이터 모델

## 원칙
모든 능력치는 시뮬레이션의 특정 결과와 연결된다. 화면에만 있고 결과에 영향이 없는 수치는 만들지 않는다.

## 능력치 스케일: 1~100
| 구간 | 의미 |
|---|---|
| 85+ | 리그 최상위, 팀당 1명 있을까 말까 |
| 75~84 | 올스타급 |
| 60~74 | 1군 주전 |
| 45~59 | 백업, 1·2군 경계 |
| ~44 | 2군, 육성 대상 |

리그 평균 주전 ≈ 60. 90 이상은 리그 전체에서 손에 꼽을 정도.

## 타자 능력치 (5)
| 능력치 | 영향 |
|---|---|
| 컨택 (contact) | 인플레이 비율, 삼진 억제, BABIP 소폭 |
| 파워 (power) | 장타·홈런 비율 |
| 선구안 (eye) | 볼넷 증가, 삼진 억제, 투구수 증가 |
| 주루 (speed) | 추가 진루, 도루, 병살 회피, 3루타 |
| 수비 (defense) | 실책 억제, 안타성 타구 처리 |

## 투수 능력치 (4) + 표시값
| 능력치 | 영향 |
|---|---|
| 구위 (stuff) | 삼진, 피안타 억제 |
| 제구 (control) | 볼넷 억제 |
| 땅볼 유도 (groundball) | 땅볼/뜬공 비율 → 피홈런·병살 |
| 체력 (stamina) | 투구수 한계, 선발/불펜 적성, 피로 회복 |
| 최고 구속 (topSpeedKmh) | **표시값**. 시뮬레이션에 직접 쓰지 않고 구위 생성 시 참고 |

## 공통 정보
- 이름, 나이, 투/타 손(좌/우/양타), 주포지션 + 포지션별 수비 적성
- 포지션: C, 1B, 2B, 3B, SS, LF, CF, RF, DH. 수비 난이도 가중치(C·SS 높음, 1B·DH 낮음)
- 계약: 연봉, 계약 잔여 연수, 계약금 잔여, FA까지 남은 시즌, 외국인 여부
- 군 복무: 군필/미필, 입대 기한 나이, 복무 중 여부와 방식
- 상태: 피로도, 부상, 폼 (08)
- 출신: 고졸/대졸/외국인, 데뷔 연도, 드래프트 정보

## 숨김 수치 (HiddenTraits)
| 항목 | 설명 | 노출 방식 |
|---|---|---|
| 잠재력 | 능력치별 최대 도달치 | 등급(A~D) 범위, 스카우트 코멘트 |
| 성장 타입 | 조기 완성 / 일반 / 대기만성 | 스카우트 추정 문구 (틀릴 수 있음) |
| 내구도 | 부상 확률 | 부상 이력으로 추측 |
| 기복 | 폼 변동 폭 | 폼 표시와 기록으로 추측 |
| 플래툰 민감도 | 좌우 상성 보정 폭 | 좌/우 분리 기록으로 추측 |
| 적응력 (외국인만) | KBO 적응 여부 | 개막 4~6주 후 기록으로 드러남 (12) |

우리 팀 선수라도 숨김 수치는 정확한 숫자로 보여주지 않는다.

## 정보 정확도 (다른 팀 선수는 흐리게)
| 대상 | 기본 정확도 | 표시 예 |
|---|---|---|
| 우리 팀 선수 | 정확 | 파워 67 |
| 타 팀 1군 | 중간 | 파워 62~72 |
| 타 팀 2군 | 낮음 | 파워 55~75 |
| 아마추어 (드래프트 풀) | 가장 낮음 | 파워 50~80 |

정확도 상승: 스카우트 집중 관찰(10), 우리 팀과의 맞대결 노출 누적.

### 구현 규칙
1. **오차는 선수마다 고정값으로 저장**한다. 화면을 열 때마다 랜덤으로 뽑지 않는다 (평균 내기 꼼수 방지). 정확도가 오르면 고정 오차가 비례해 줄어든다.
2. **진짜 값이 범위 중심에 오지 않게** 한다. 고정 오차가 범위 중심 자체를 치우치게 만든다.
3. AI 구단도 완벽한 정보를 쓰지 않는다. AI 평가에도 구단별 오차를 적용한다.
4. 조회는 반드시 `ScoutingView`를 통한다 (CLAUDE.md 원칙 4).

## 좌우 상성 (플래툰)
- **리그 공통 보정**: 같은 손 매치업이면 타자 불리, 반대 손이면 유리
- **선수별 플래툰 민감도**(숨김): 보정 폭의 배율. 대부분 작고 일부만 큼. 좌타자가 평균적으로 더 큼
- **양타**: 항상 반대 손 타석. 대신 성장 속도 소폭 감소
- 투수도 좌타/우타 상대 보정을 가진다
- 모든 기록은 좌투/우투(투수는 좌타/우타) 상대로 분리 저장 → 민감도가 기록으로 드러남
- 사전 지시(06)에 좌완용/우완용 라인업 두 벌이 필수

## Kotlin 모델 초안
```kotlin
sealed class Player {
    abstract val id: PlayerId
    abstract var name: String
    abstract var age: Int
    abstract val throws: Hand
    abstract val bats: Hand          // L, R, S(양타)
    abstract var contract: Contract
    abstract var military: MilitaryStatus
    internal abstract val hidden: HiddenTraits   // UI에서 접근 불가
    abstract var condition: Condition            // 피로, 부상, 폼
}

data class BatterRatings(val contact: Int, val power: Int, val eye: Int, val speed: Int, val defense: Int)
data class PitcherRatings(val stuff: Int, val control: Int, val groundball: Int, val stamina: Int)
```
실제 구조(투타 겸업 불필요, 모든 선수는 타자 또는 투수)는 구현 시 확정한다.
