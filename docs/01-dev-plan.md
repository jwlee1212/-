# 01. 개발 계획 (2026-10-05)

컨셉은 `00-concept.md`, 디자인은 `02-design.md`. 손맛이 걸린 마일스톤은 **폰에서 유저 확인**까지가 완료 기준이다.

## G0. 정리 + 타격 프로토타입 (완료, 2026-10-05)
- Godot 4.7.2 설치, 웹 템플릿 설치
- 타격 프로토타입: 탭 타이밍 판정, 직구·변화구, 능력치 슬라이더, 소리 합성, 히트스톱·흔들림·파편·꽃가루, FPS, 웹 빌드
- Kotlin 코드·옛 문서 정리 (태그 `pre-godot`에 보존)
- 완료: 테스트 11건 통과, 유저가 폰에서 "나쁘지 않다"

## G1. 타격 완성
- 투수 볼배합: 카운트에 따라 구종·코스가 달라짐 (유인구, 결정구)
- 존 조준(노려치기): 공이 오기 전 존의 한 구역을 찍어 두면 그 코스에 오면 판정 폭↑, 아니면↓ (선택 사항 — 손맛 확인 후 결정)
- 타구 결과에 방향별 간단한 수비 확률 (아직 수비수 없음)
- 연출: 투수·타자 동작 개선, 타격음 변주
- 완료: 판정·볼배합 테스트, 폰 확인

## G2. 투구
- 구종(직구·슬라이더·커브·체인지업 중 3~4개)·코스 선택 → 제구 게이지 타이밍
- 타자 AI: 능력치·카운트에 따라 스윙 결정, 같은 타격 판정 규칙을 거꾸로 사용
- 투구 수·체력
- 완료: 타자 AI 분포 테스트(능력치에 따른 삼진·볼넷·피안타 비율), 폰 확인

## G3. 수비
- 내 쪽으로 온 타구만: 낙구 지점 표시 → 끌어서 이동 → 탭 포구 → 스와이프 송구
- 포지션별 상황 3~4개 (외야 뜬공, 내야 땅볼, 투수 앞 타구)
- 완료: 포구·송구 판정 테스트, 폰 확인

## G4. 한 경기
- 타석 단위 자동 시뮬레이션 (옛 Kotlin 엔진의 Log5 방식을 참고해 GDScript로, `docs/engine/04~05`)
- 내 차례가 오면 조작 화면으로 전환, 아니면 문자 중계·하이라이트로 빠르게
- 점수판, 이닝 진행, 주자
- 완료: 경기 무결성 테스트(점수·아웃·주자 수), 재현성

## G4.5. 첫 플레이어블
- 고교 한 경기를 폰에서 처음부터 끝까지
- 완료: 유저 피드백. **재미 검증 — 부족하면 G5 전에 고친다**

## G5. 시즌·성장
- 주간 루프: 훈련 배분 → 경기 → 결산
- 능력치 성장(훈련·경기 성과), 컨디션·폼, 부상
- 고교 한 학년 시즌
- 완료: 성장 곡선 테스트, 한 학년 자동 진행

## G6. 돌발 이벤트·스토리
- 이벤트 정의 데이터(JSON): 조건, 등장인물, 대사, 선택지, 즉시·지연 결과
- 고교 3년 메인 서사, 라이벌, 진로 선택
- 완료: 이벤트 무결성 테스트, 폰에서 고교 3년 플레이

## G7. 드래프트·프로
- 드래프트, 대학·독립리그 경로
- 프로 리그 자동 진행(다른 팀 경기), 2군→1군, 연봉·FA, 군 입대, 노쇠·은퇴
- 커리어 연대기
- 완료: 장기 밸런스 테스트(자동 커리어 여러 번)

## G8. 캐주얼 비주얼
- SD 캐릭터 스프라이트·애니메이션 (투구·스윙·포구·송구·주루)
- 파츠 조합 아바타, 화면 전체 다듬기, 다크 모드

## G9. 세이브·밸런싱·출시
- 세이브/불러오기, 난이도, 튜토리얼

- 게임 이름·상표 확인, 스토어 준비, 웹 빌드 용량 줄이기(맞춤 템플릿)
