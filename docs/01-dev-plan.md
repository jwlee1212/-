# 01. 개발 계획 (스카우터, 2026-10-05)

컨셉은 `00-concept.md`, 디자인은 `02-design.md`. 이전 단장 시뮬레이션의 M0~M5(엔진)는 완료 상태로 재사용한다.

## S0. 정리
- 옛 화면(`app/` 화면·세션·화면 테스트)과 콘솔(`cli/`) 제거
- 옛 기획 문서 정리: 엔진 참고 문서는 `docs/engine/`으로 이동, 유저 시점 기획(경영·게임 흐름·옛 디자인·옛 개발 계획)은 삭제 (태그 `pre-redesign`에 보존)
- 빈 앱 셸: 데스크톱·웹·iOS 진입점이 "준비 중" 타이틀을 띄운다
- 완료: 엔진·도구 테스트 전부 통과, 앱이 세 타깃 모두 컴파일

## S1. 아마추어 세계
- 고교(가상 학교명) 생성, 학교마다 선수 명단 (1~3학년), 지역 권역
- 고교 선수 능력치 스케일: 기존 유망주 생성기(`ProspectFactory`) 재사용, 학년별 성장
- 대회 일정 (주말 리그·전국 대회 4~5개, 3~8월)
- 고교 경기 시뮬레이션: 기존 `GameSimulator`를 그대로 쓰되 고교용 환경값(실책 많음, 투수 혹사 등)은 balance.json에서
- 완료: 한 시즌 고교 대회가 끝까지 돌고 박스스코어 검증 실패 0, 같은 시드 → 같은 결과

## S2. 관찰
- 주간 행동: 시간 슬롯(예: 주 3칸)과 출장비로 대회·학교·선수 방문을 고른다
- 관찰: 방문한 경기의 실제 결과 + 관찰 카드 → 그 선수의 정밀도 상승 (기존 `ScoutingPrecision` 확장)
- 관찰 카드: 숨김 수치 → 정성적 문장. 문장 풀은 데이터 파일
- 표본의 함정: 정밀도와 별개로 "눈에 보인 성적"이 운에 흔들림
- 완료: 정보 은닉 테스트, 관찰 수렴 테스트

## S3. 돌발 이벤트
- 이벤트 정의 데이터(JSON): 발생 조건, 등장인물, 대사, 선택지, 즉시 결과, 지연 결과(몇 주·몇 년 뒤)
- 스카우터 상태값: 평판, 청렴도(숨김), 인맥, 예산
- 이벤트가 숨김 수치와 연결됨 (찌라시의 진위 = 선수의 실제 성향)
- 기존 `events/Incidents`, `season/IncidentDesk` 구조를 검토해 쓸 수 있는 건 재사용
- 1차 이벤트 10~15종 (`00-concept.md` §5-2)
- 완료: 이벤트 무결성 테스트, 주당 이벤트 0~2개 분포 확인

## S3.5. 첫 플레이어블 (폰 테스트)
- 최소 화면: 이번 주 일정 고르기 → 관찰 결과 → 이벤트 카드 → 선수 파일
- 그림은 임시(도형·이모지 없이 단색 아이콘), 애니메이션은 카드 등장 정도만
- 웹 빌드로 폰에서 한 시즌(3~8월) 플레이
- 완료: 유저가 폰으로 한 시즌을 끝까지 해 보고 피드백. **여기서 재미 검증 — 재미없으면 S4 전에 루프를 고친다**

## S4. 드래프트
- 빅보드(내 추천 순위) 작성
- 스카우트 회의: 내 평판·근거(정밀도)·구단 필요가 설득 성공률을 정한다
- 드래프트 당일: 타 구단 AI 지명(`DraftAI` 재사용), 연출
- 완료: 드래프트 결과가 배경 리그 선수로 정상 편입

## S5. 시간 점프·커리어
- 겨울에 배경 리그를 자동 진행 (`season/` + `AutoAdvance`)
- 적중률: 내가 추천한 선수·거른 선수의 프로 성적으로 매긴다
- 평판 → 승진(담당 지역 확대)·이직·해고, 엔딩 후보
- 커리어 연대기 ("2027년 내가 3라운드에 민 투수, 2031년 다승왕")
- 완료: 20시즌 자동 커리어 테스트 (장기 밸런스 유지)

## S6. 캐주얼 비주얼
- SD 캐릭터 시스템(파츠 조합 벡터 아바타), 주요 인물 일러스트
- 애니메이션: 카드 뒤집기, 이벤트 등장, 드래프트 호명, 범위 막대 "안개 걷힘"
- 효과음·햅틱(선택)

## S7. 세이브·밸런싱·출시 준비
- 세이브/불러오기, 난이도, 튜토리얼
- 게임 이름·상표 확인, 스토어 준비

## 백로그 (나중에 검토)
- 대학·독립리그 선수
- 해외 유턴파, 외국인 스카우트
- 라이벌 스카우터 캐릭터 서사
