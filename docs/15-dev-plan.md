# 15. 개발 계획

## 확정 사항
- **Kotlin + Kotlin Multiplatform** (Android + iOS), UI는 Compose Multiplatform
- **위임 모드**: Claude Code가 구현, 유저는 리뷰. 마일스톤마다 `docs/dev-log.md` 기록 (CLAUDE.md §3)

## 마일스톤 상세

### M0. 프로젝트 세팅
- KMP 프로젝트, `engine`(commonMain), `tools`·`cli`(jvmMain)
- kotlinx.serialization, kotlin.test
- `config/balance.json`, `data/teams.json` 로더
- 완료: 빈 테스트 통과, JSON 로드 테스트 통과

### M1. 모델 + 리그 생성기 (docs 02, 03)
- 선수·팀·계약·군 복무·숨김 수치 모델
- `ScoutingView` 뼈대 (정보 은닉 구조를 처음부터)
- `LeagueGenerator` (시드 입력), 이름 생성, 아키타입, 팀 템플릿
- 일정표 생성 (3연전 4 + 2연전 2, 24주)
- 감독·코치·메디컬·AI 단장 데이터 생성
- 완료: `data/league_2026.json` 생성, 10팀 전력이 `teams.json` 목표 ±2, 같은 시드 → 동일 결과

### M2. 경기 시뮬레이션 (docs 04, 05)
- Log5, 능력치 변환표, 단계별 타석 결정, 보정
- 경기 상태, 주루, 도루·폭투, 실책·자책점, 투수 기록 판정
- `GameEvent` 스트림, `StatsRecorder`(1단계 지표, 좌우 분리), `BoxScoreValidator`
- 임시 고정 라인업·단순 교체로 테스트
- 완료: 1,000경기 검증 실패 0

### M3. 사전 지시 + 감독 AI (doc 06)
- `DirectiveSheet` 슬롯, 프리셋, 예외 처리 우선순위
- 감독 성향 → 규칙표 생성
- 완료: 투수 교체·대타·불펜 역할이 규칙대로 동작하는 시나리오 테스트, 11회 연장에서 투수 고갈 시에도 경기 완료

### M4. 주간 루프 + 컨디션 (docs 07, 08)
- 캘린더, 주간 결정·진행·결산, 엔트리 규칙, 2군 추정 성적
- 피로, 부상(영구 하락 포함), 폼
- 콘솔 UI로 한 시즌 진행, 자동 진행
- `Calibrator` 도구: 100시즌 리그 평균 출력, 변환표 조정
- 완료: 캘리브레이션 목표 범위 도달, 1,000시즌 검증 실패 0

### M5. 성장·노화·은퇴 (doc 09)
- 월별·시즌 후 성장, 능력치별 곡선, 출장 보정, 코치 재분배, 각성·급노쇠, 은퇴
- 임시 드래프트(단순 생성 유입)로 선수 수 유지
- 완료: 30시즌 밸런스 테스트 통과
- **= 프로토타입 완성**

### M6. 스카우트·드래프트 (doc 10)
- 정보 정확도·고정 오차, 투자 단계, 집중 관찰, 주간 리포트
- 9월 드래프트, AI 지명, 계약금, 육성선수
- 지명권 가치표 생성 도구, 지명권 트레이드
- 완료: UI 계층이 진짜 값에 접근 불가(컴파일 수준), 드래프트 AI 편향 동작

### M7. FA·트레이드 (doc 11) + 2·3단계 지표 (doc 04)
- 가치 평가, 구단 모드, 포지션 필요도
- FA 등급·보상, 경쟁 입찰, 역제안, 에이전트 정보, 계약금/연봉 분리, 비FA 다년계약
- 트레이드 AI, 협상 피로도, AI끼리 거래
- 소프트캡 제재
- wOBA, wRC+, FIP, ERA+, WAR, 리그 상수, 구장 보정
- 완료: 자동 테스트 봇이 AI 상대 이득 거래를 쉽게 반복하지 못함 (꼼수 방지 검증)
